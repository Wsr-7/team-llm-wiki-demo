# 种子动员工具包（Phase 0 Step 0.3）

> 用途：宣讲会后直接开动员。以下模板可原样粘贴到 Teams / 邮件，占位符 `<...>` 替换后即用。

## 1. 动员帖模板（Teams 频道直接发）

```text
【招募】团队知识库首批种子贡献者 (15-25 人)

我们把散落在 Confluence/聊天记录/个人脑子里的排障经验、runbook、系统知识
收进一个 git 管理的知识库 <repo URL>，人和 AI Agent (Copilot 等) 都能直接查。
设计宣讲材料: <repo URL>/docs/llm-wiki-architecture-v3/05-工作流场景图解.md

现在招首批种子贡献者，你要做的只有一件事:
  认领 1-2 个"最近半年被别人问过至少两次的问题"，写成页面 (可以让 AI 代写,
  你只负责提供材料和审核)。每页 15-30 分钟，两周内完成即可。

怎么认领: 在下面的认领表回帖 (问题 + 你的名字)。
怎么写: 见 <repo URL>/README.zh-CN.md 的"怎么贡献" (三步: 复制模板→填两个
字段→发 PR)。最省事的方式: 把材料直接丢给 Copilot/agent, 让它按仓库里的
prompts/capture.md 整理, 你只审核。

优先要这些内容: 生产问题的排障记录 > 操作手册 > 系统介绍 > 术语。
```

## 2. 认领表模板

| # | 问题（被问过 ≥2 次的） | 类型 | 认领人 | 目标目录 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 1 | 例：支付网关 502 突增怎么排查 | troubleshooting | @<name> | wiki/troubleshooting/ | 认领 |
| 2 | 例：对账批量任务如何安全重启 | runbook | @<name> | wiki/runbooks/ | 认领 |
| 3 | 例：checkout 服务的边界和依赖是什么 | system | @<name> | wiki/systems/ | 认领 |
| 4 | 例：为什么当初选了 Kafka 而不是 MQ X | decision | @<name> | wiki/decisions/ | 认领 |
| … | | | | | |

选题提示（帮成员想选题的四个问题）：最近一次生产事故你是怎么定位的？新人入职最常问你什么？哪个操作你每次做都要翻旧聊天记录？哪个"为什么这么设计"只有老人知道答案？

## 3. 贡献三行版（给认领人的最短说明）

```text
1. 有材料没时间 → 材料(URL/粘贴/口述)丢给 agent: "按 prompts/capture.md 整理进知识库"
2. 想直接写 → 复制 templates/ 对应模板, 填 owner + updated, 写正文, 发 PR
3. 不确定放哪 → 先扔 inbox/ (建个 md 随便写, PR 自合, 园艺例会替你归位)
```

## 4. 常见问题（动员时会被问的）

- **"我英文写作慢"** → inbox 收中文，正式页让 agent 翻译，你只审核事实对不对。
- **"我写的东西会不会被喷"** → inbox 零审核；正式页只有域 owner 一人 review，review 的是事实和证据，不是文笔。
- **"以后谁维护"** → 双周园艺例会 + 轮值园丁 + 21 天停摆自动报警，不靠自觉。
- **"和 Confluence 什么关系"** → 引用贴链接；被反复查的页按需搬进来并在原页标注停止维护；后期会把 wiki 单向发布回 Confluence 给不用 git 的同事看。

## 5. 第一期园丁 checklist（动员两周后）

```text
□ 拉最新 main, 跑 prompts/gardening.md (agent 代办, 你只审)
□ 认领表逐行核对: 已完成/进行中/需要帮助
□ gardening PR 例会过一遍, 合并
□ 在频道发第一期简报: 页数 / 贡献者数 / 本期最有用的一页 (给贡献者可见的正反馈)
□ 指定下一期园丁
```
