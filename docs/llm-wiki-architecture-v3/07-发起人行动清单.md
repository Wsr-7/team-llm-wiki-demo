# 07 — 发起人行动清单（个人版，按时间顺序）

> 这是**你个人**要做的事，按先后排序，含每步耗时、参考文档、以及"什么时候进入哪个 Phase"。
> 与 03 的区别：03 是项目视角的 Phase 计划；本文是你的待办表。
> 用法：直接在本文件上打勾（改 `[ ]` 为 `[x]`），它本身就是你的进度记录。

## 阶段 ①：宣讲前（半小时内可完成）

- [ ] **1. 合并 PR #3 到 main**（1 分钟）
  https://github.com/Wsr-7/team-llm-wiki-demo/pull/3 —— 合并后 main 才是宣讲版结构。
- [ ] **2. 把自己加进 `team/people.md`**（3 分钟）
  真实 staff-id + GitHub username + 负责域；顺手把 `wiki/glossary.md` 的 owner 从
  `staff:00000000` 改成你自己（消掉最后一个 check warning）。规则：`schemas/person.md`。
- [ ] **3. 备课**（20 分钟）
  过一遍 [05-工作流场景图解](05-工作流场景图解.md)（投屏主材料）；被挑战设计取舍时用
  [01](01-当前设计问题分析.md) 和 [06](06-对抗性审查.md)；动员话术在 [`docs/seed-kit.md`](../seed-kit.md)。

## 阶段 ②：宣讲日

- [ ] **4. 宣讲**（30 分钟）
  主线一句话："inbox 随手扔，PR 是审核台，wiki 是可信区；AI 干整理的活，人只做判断"。
- [ ] **5. 现场演示一次捕获**（3 分钟，强烈建议）
  随便找一条真实经验丢给 agent → inbox 条目 → PR 自合，让大家看到"5 分钟"不是口号。
- [ ] **6. 发动员帖 + 认领表**（5 分钟）
  模板直接抄 [`docs/seed-kit.md`](../seed-kit.md) §1-§2，目标 15-25 名种子贡献者。

## 阶段 ③：宣讲后一周内（管理员/协调动作）

- [ ] **7. 建 GitHub team 并替换 CODEOWNERS 占位符**（30 分钟，需要 org 权限或找 repo 管理员）
  `@org/knowledge-admins` 换成真实 team（建议 2-3 人）；域级行等认领表出来后补（见第 12 步）。
- [ ] **8. 开 branch protection**（15 分钟）
  按 [`docs/branch-protection.md`](../branch-protection.md) 逐项勾选：require PR、CODEOWNERS
  review、**approvals=0**、required check、开启 push protection、bot bypass。
- [ ] **9. 找 Jenkins 管理员建 CI job**（转发 [`docs/ci.md`](../ci.md) 即可，管理员约 30 分钟）
  J1 必做（根目录 `Jenkinsfile`，设为 merge 门禁）；J3 建议（`jenkins/gardening-watchdog.Jenkinsfile`）；
  J2 可先不做（降级方案：园丁双周重建 INDEX）。
- [ ] **10. 打通 agent 入口**（30 分钟）
  建 Copilot Space 挂载本 repo；在 1-2 个主力业务 repo 的 copilot-instructions.md 加一行
  "团队知识库在 <repo URL>，排障/规范问题先查它"。
- [ ] **11. 向管理层要两件事**（一次沟通——这是 06 §6 指出的系统存活关键，别跳过）
  ① 园丁轮值的时间预算（每期约 1 小时）写进团队预期；② 事故关单流程加一项"inbox 条目链接"。

## 阶段 ④：种子期，第 1-2 周（= 03 的 Phase 0 Step 0.3）

- [ ] **12. 维护认领表 + 补 people.md + 补域级 CODEOWNERS**（随认领进展，累计约 1 小时）
  每个种子成员进 people.md；每个被认领的域加一行 `/wiki/<type>/<domain>/ @org/<team>`。
- [ ] **13. 自己打样 1-2 页**（30 分钟）
  把材料丢给 agent 走完整流程（capture → 正式页 PR → 你自己当 reviewer），产出团队的第一个真实范例。
- [ ] **14. 盯种子 PR 收口**（两周内零散进行）
  验收线（03 Phase 0）：≥15 个真实页面、每个种子成员当过一次贡献者和一次 reviewer、check 全绿。

## 阶段 ⑤：进入运转，第 3 周起（= 进入 Phase 1）

- [ ] **15. 排园丁轮值表**（10 分钟）
  写进 `team/people.md` 的 notes 列；**自己当第一期园丁**，照 [`docs/seed-kit.md`](../seed-kit.md) §5 的 checklist 跑。
- [ ] **16. 双周节拍跑 6 周**（每期：园丁 1 小时 + 例会 30 分钟）
  第 6 周对照 03 的 Phase 1 验收：≥40 页、活跃贡献者 ≥15、回答率 ≥50%、≥3 次回填合并。
  不达标 → 解法是例会上把 unknown 清单变认领任务（补内容），**不是加机制**。

## 阶段 ⑥：之后 —— 等触发器，不主动做事（= Phase 2-4）

这一阶段你唯一的工作是**识别信号**（多数会在园艺例会上自然浮现），对号入座：

| 信号出现 | 你做的事 | 参考 |
| --- | --- | --- |
| 连续两期例会出现"页面存在但 agent 没找到" ≥3 例，或 wiki >150 页 | 启动检索增强（T2） | 03 Phase 2 |
| 非 git 同事第 3 次抱怨看不到（预期第一季度内） | 启动 repo→Confluence 单向发布（T3） | 03 Phase 3 |
| 某类 inbox 整理动作每次雷同 / 需要程序化查询 / 出现外部消费方 | 对应自动化/查询服务/OKF 导出（T4） | 03 Phase 4 |
| inbox 每周期积压 >15 条 | 园艺按域拆分 | 02 §10 |
| 有人想给 AGENTS.md 加第 151 行 | 拒绝或先减后加 | 06 §R13 |
