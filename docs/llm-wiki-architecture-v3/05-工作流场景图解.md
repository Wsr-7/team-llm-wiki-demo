# 05 — 工作流场景图解（宣讲版）

> 用途: 团队宣讲会材料。每个场景 = 一张图 + 编号步骤 + 成本标注。
> mermaid 图在 GitHub 网页端直接渲染。

## 0. 全景：三层结构 + 一条流水线

```mermaid
flowchart LR
    subgraph capture["捕获 (零门槛)"]
        A[事故/排障/讨论/经验] --> B[inbox/ 未审条目]
    end
    subgraph review["审核 (GitHub 原生)"]
        B -->|双周园艺: agent 起草| C[Pull Request]
        A -->|内容已成形: 直接| C
        C -->|owner review + CI| D[wiki/ 正式知识]
    end
    subgraph consume["消费 (任意入口)"]
        D --> E["人: GitHub/INDEX"]
        D --> F["Agent: Copilot / Claude Code /\nopencode / 内部模型"]
        F -->|高价值回答回填| C
    end
```

一句话讲给团队听：**inbox 随手扔，PR 是审核台，wiki 是可信区；AI 干整理的活，人只做判断。**

三个角色：

| 角色 | 做什么 | 成本 |
| --- | --- | --- |
| 每个成员 | 遇到值得记的事扔进 inbox（或让 agent 整理）；有问题先问 agent | ≤5 分钟/次 |
| 轮值园丁（每期 1 人） | 双周跑一次园艺 prompt，审 agent 产出的整理 PR | ~1 小时/两周 |
| 域 owner | 审自己领域的知识 PR | 随 PR 发生 |

---

## 场景 A：快速捕获（刚解决了一个生产问题）

```mermaid
sequenceDiagram
    actor Dev as 成员
    participant Agent as 任意 Agent
    participant Inbox as inbox/
    Dev->>Agent: "帮我记一下: 刚才批量任务超时是连接池没调, 贴聊天记录…"
    Agent->>Agent: 按 prompts/capture.md 提取事实+保留原文引用(英文输出)
    Agent->>Inbox: 写入 2026-07-07-batch-timeout.md, 直接 commit
    Agent-->>Dev: 已记录, 园艺例会时会整理成正式页
```

步骤：① 把材料丢给 agent（贴 URL / 粘聊天记录 / 口述）→ ② agent 生成 inbox 条目（英文，含 Raw notes 原文引用）→ ③ 直接 commit，结束。**没有 frontmatter、没有审批、没有格式要求。**

> 不用 AI 的版本：自己建个 md 文件写三行，一样合法。

## 场景 B：原始资料 → 正式 wiki 页面

```mermaid
sequenceDiagram
    actor Dev as 成员
    participant Agent as Agent
    participant PR as Pull Request
    participant Owner as 域 Owner
    participant Wiki as wiki/
    Dev->>Agent: "把这份 Confluence 排障记录入库" (贴 URL 或正文)
    Agent->>Agent: 查重(grep wiki/) → 选模板 → 提取+关键证据摘录
    Agent->>PR: 新页面草稿 (frontmatter: owner/updated/sources)
    Note over PR: CI 自动跑 npm run check
    Owner->>PR: review (来源可信? 步骤对? owner 对?)
    PR->>Wiki: merge → 成为正式知识, INDEX 更新
```

步骤：① 递材料 → ② agent 查重、选模板、编译成英文页面（sources 指回原链接 + 关键原文摘进 "Source excerpts"）→ ③ 开 PR，CI 校验格式/链接/owner → ④ 域 owner 审核合并。**候选层就是 PR 本身**——审核意见、修改记录、拍板结论全在 PR 里，不需要额外流程。

## 场景 C：查询（日常使用最高频）

```mermaid
flowchart TD
    Q[提问: 支付网关 502 怎么处理?] --> I[Agent 读 INDEX.md 选候选页]
    I -->|不够| G[grep wiki/ 关键词+同义词]
    I --> R[读候选页全文 2-5 页]
    G --> R
    R --> S{有答案?}
    S -->|有| A["带引用回答<br/>Based on: wiki/troubleshooting/…"]
    S -->|多页冲突| CF["按优先级裁决: status > 位置 ><br/>owner > 时效; 真冲突则两个都摆出来"]
    S -->|没有| U["返回 unknown + 建议该建哪页<br/>+ 主动提议起草 inbox 条目"]
    A --> FB{回答有沉淀价值?}
    FB -->|有| P[起草页面回填 → PR]
```

上下文预算（讲给关心"塞爆上下文"的同事）：协议 ~1k + INDEX ~2-5k + 命中页 ~3-10k tokens，**15k 以内**，内部小模型也够用。

## 场景 D：双周园艺（唯一的例行治理）

```mermaid
sequenceDiagram
    actor G as 轮值园丁
    participant Agent as Agent
    participant PR as gardening PR
    actor Team as 团队 (例会 10 分钟)
    G->>Agent: 跑 prompts/gardening.md
    Agent->>Agent: inbox 分类(晋升/合并/保留/丢弃)<br/>+ 健康报告(过期/断链/needs-review/超长页)
    Agent->>PR: 一个 PR: 起草的正式页 + 机械修复 + 报告 + 三个度量
    Team->>PR: 例会过一遍: 合并/退回/认领 needs-review
    PR->>PR: merge, 本周期结束
```

节拍：每两周 30 分钟例会 + 园丁 1 小时。三个度量写在 PR 描述里：回答率 / 鲜活度 / 贡献面。**inbox 的质量债在这里还，不在捕获时卡。**

## 场景 E：知识过时与取代（supersede）

```mermaid
flowchart LR
    N[新做法产生] --> PR2[新页面 PR]
    PR2 -->|同一个 PR 内| O["旧页加:<br/>status: superseded<br/>superseded_by: 新页路径<br/>+ 页首横幅指向新页"]
    O --> K[旧页正文保留 = 历史语境]
    K --> AG["agent 行为: 永不引用 superseded 页<br/>自动顺 superseded_by 找新页"]
```

存疑但还没有替代品时：只标 `status: needs-review`，agent 引用时自动附带"此页待确认"警告，园艺例会认领核实。**没有 confidence 打分，只有三种状态：现行 / 待确认 / 已取代。**

## 场景 F（未来，触发后才建）：对外发布与搜索层

```mermaid
flowchart LR
    W[wiki/ 纯 markdown] -->|"T3 触发: 非 git 同事看不到"| CF["单向发布到只读 Confluence space<br/>(现成工具, merge 时自动)"]
    W -->|"T4 触发: 程序化消费需求"| S["检索原语 list/search/get<br/>(CLI 或 MCP, 无状态只读)"]
    S --> C1[IDE agent]
    S --> C2["网页知识客服<br/>(薄 UI + query prompt + 内部模型)"]
    S --> C3[Teams bot]
```

宣讲话术：**今天不建任何服务**。知识是纯文件，未来所有服务都只是"会读文件的客户端"——所以什么时候建都不晚，且永远可以整体重建。
