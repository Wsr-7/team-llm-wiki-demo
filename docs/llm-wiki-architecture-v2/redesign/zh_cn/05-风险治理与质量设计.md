# 风险、治理与质量设计 (Risk, Governance, And Quality Design)

> 目的：为重新设计的团队 LLM Wiki 定义主要风险、治理控制、质量门禁和运营安全保障。

## 1. 核心风险论点 (Core Risk Thesis)

团队 LLM Wiki 的主要风险不在于检索失败。主要风险在于系统会随着时间的推移变得自信但错误。

常见的故障模式：

```text
过时知识仍然保持活跃状态
AI 生成的文本未经审查就被接受
来源证据缺失或过于粗糙
新旧主张相互矛盾
个人笔记泄漏到团队真知中
受限内容进入默认搜索结果
索引和图谱侧车与规范 Markdown 发生漂移
自动化静默地修改正式知识
```

设计必须优先考虑信任、溯源和生命周期，其次才是搜索智能。

## 2. 风险登记册 (Risk Register)

| 风险 | 描述 | 影响 | 缓解措施 | 阶段 |
| --- | --- | --- | --- | --- |
| Lint 边界污染 | 演示或设计示例未通过正式检查 | 中等 | 路径策略和正式检查范围 | Phase 0 |
| 原始来源突变 | 来源证据在无追踪的情况下发生变化 | 高 | SHA256 源哈希和不可变来源规则 | Phase 0 |
| 弱 YAML 解析 | 嵌套元数据解析错误 | 高 | 真正的 YAML 解析器和 JSON Schema 验证 | Phase 0 |
| 虚假活跃演示知识 | 演示页面被当作真实指南使用 | 高 | 将演示标记为草稿或非生产状态 | Phase 0 |
| 手动索引漂移 | 索引遗漏或错误描述页面 | 中等 | 生成索引和 check-index | Phase 0.5 |
| 过时活跃页面 | 旧指南被当作当前事实使用 | 高 | review_after 检查和审查队列 | Phase 0.5 |
| 已废弃页面误用 | 已被替代的指南仍然被引用 | 高 | superseded 引用检查 | Phase 0.5 |
| 粗糙溯源 | 页面来源存在但主张支持不清晰 | 高 | 高风险主张的 claim_refs | Phase 0.5 |
| AI 幻觉产生的正式知识 | Agent 撰写看似合理但无依据的内容 | 高 | 候选缓冲区、负责人审查、引用门禁 | Phase 1 |
| 负责人不明确 | 无人对页面正确性负责 | 高 | 必需负责人和 CODEOWNERS | Phase 1 |
| 候选质量差异 | AI 提案在结构和证据方面各不相同 | 中等 | 候选质量评分 | Phase 1 |
| 搜索过时误用 | 搜索将过时/已废弃页面排名过高 | 高 | 查询评估和基于状态的排名 | Phase 2 |
| 敏感内容泄漏 | 受限内容进入搜索/导出 | 严重 | index_policy、秘密扫描、导出过滤器 | Phase 2 |
| 图谱虚假边 | 推断出的关系被当作可信的 | 中等 | 仅限确定性边来源 | Phase 3 |
| OKF 导出丢失治理信息 | 外部导出隐藏内部状态/置信度 | 中等 | 跨团队扩展字段 | Phase 4 |
| 自动化越权 | Agent 开启或合并不安全变更 | 严重 | 仅限自动化 PR，不自动合并 | Phase 5 |
| 平台权威漂移 | MCP/API 被视为感知上的事实来源 | 高 | repo 保持权威，仅产生派生制品 | Phase 6 |

## 3. 治理模型 (Governance Model)

### 3.1 角色 (Roles)

| 角色 | 职责 |
| --- | --- |
| 知识管理员 (Knowledge Admin) | 负责 schema、prompt、模板、治理策略、CI 检查 |
| 领域负责人 (Domain Owner) | 审查领域页面并确认正式知识 |
| 贡献者 (Contributor) | 添加来源、提出候选、回答审查问题 |
| AI Agent | 按照协议进行摄取、编译、检查、提出和查询 |
| Repo 管理员 (Repo Admin) | 配置分支保护、CODEOWNERS 和 CI |

### 3.2 权威规则 (Authority Rules)

```text
raw/ 是来源证据，而非综合知识。
inbox/candidates/ 是提案空间，而非事实真相。
wiki/ 是经过审查后的正式团队真相。
confluence-mirror/ 是外部快照证据，而非事实真相。
personal/ 是个人上下文，而非团队真相。
indexes/、graph/、okf/ 是派生投影。
```

### 3.3 写入权限 (Write Authority)

| 路径 | 人类直接写入 | AI 直接写入 | 是否需要 PR |
| --- | --- | --- | --- |
| `raw/source.md` | 仅可添加 | 不可重写 | 是 |
| `raw/manifest.md` | 是 | 仅辅助 | 是 |
| `inbox/candidates/` | 是 | 是 | 正式化前可选 |
| `inbox/reviews/` | 是 | 是 | 可选 |
| `wiki/` | 是 | 仅限补丁提案 | 是 |
| `schemas/` | 仅管理员 | 仅限补丁提案 | 是 |
| `prompts/` | 仅管理员 | 仅限补丁提案 | 是 |
| `templates/` | 仅管理员 | 仅限补丁提案 | 是 |
| `indexes/` | 生成 | 生成 | 是 |
| `graph/` | 生成 | 生成 | 是 |
| `okf/` | 生成 | 生成 | 是 |
| `logs/` | 追加 | 受控追加 | 是或受控自动化 |

## 5. 页面质量模型 (Page Quality Model)

### 5.1 置信度与质量 (Confidence Versus Quality)

不要混淆置信度和质量。

```text
confidence = 事实的可靠程度
quality = 页面的有用性、结构性、引用完整性和可维护性
```

一个页面可以质量高但置信度低（如果证据薄弱）。一个页面可以事实置信度高但结构质量差。

### 5.2 候选质量评分 (Candidate Quality Score)

候选应包含：

```yaml
quality:
  structure_score: 0.00
  citation_score: 0.00
  consistency_score: 0.00
  actionability_score: 0.00
  owner_clarity_score: 0.00
  overall: 0.00
quality_status: pass | needs-rewrite | needs-human-review
```

建议阈值：

| 质量状态 | 规则 |
| --- | --- |
| `pass` | overall >= 0.75 且 citation_score >= 0.70 |
| `needs-human-review` | overall 0.50-0.75 或负责人不明确 |
| `needs-rewrite` | overall < 0.50 或缺少来源引用 |

### 5.3 正式页面质量检查清单 (Formal Page Quality Checklist)

页面变为活跃状态前：

```text
[ ] Owner 真实有效。
[ ] 来源引用 (Source refs) 存在。
[ ] 高风险主张有 claim ref 或明确的审查备注。
[ ] Status 和 review_state 一致。
[ ] 置信度理由 (Confidence rationale) 可解释。
[ ] 相关链接 (Related links) 可解释。
[ ] 页面包含在生成的索引中。
[ ] 敏感内容策略明确。
[ ] review_after 对页面类型适当。
```

## 6. 置信度与生命周期规则 (Confidence And Lifecycle Rules)

### 6.1 基准置信度范围 (Baseline Confidence Ranges)

| 置信度 | 含义 |
| --- | --- |
| 0.00-0.30 | 无依据、推测性或已拒绝 |
| 0.30-0.50 | 来源薄弱或未审查的候选 |
| 0.50-0.75 | 有来源支持且经管理员分诊 |
| 0.75-0.90 | 经负责人审查的活跃知识 |
| 0.90-1.00 | 经审计支持、ADR 支持、生产验证或多来源支持 |

### 6.2 硬性规则 (Hard Rules)

```text
active page 必须包含 source_refs。
disputed page 的置信度不得高于 0.60。
superseded page 不得用作当前指导。
superseded page 必须包含 superseded_by。
review_after 到期将创建审查队列条目。
confidential page 不得进入默认 OKF 导出。
restricted page 未经策略允许不得进入默认搜索。
```

### 6.3 审查节奏 (Review Cadence)

| 页面类型 | 默认审查周期 |
| --- | --- |
| runbook | 90 天 |
| system | 180 天 |
| decision | 365 天，除非决策明确有时间限制 |
| glossary | 365 天 |
| practice | 180 天 |
| learning | 无强制过期，但可归档 |
| mirrored | 跟随来源同步策略 |

## 7. 隐私与敏感内容 (Privacy And Sensitive Content)

### 7.1 敏感级别 (Sensitivity Levels)

```text
internal: 正常的团队内部内容
restricted: 有限受众或团队特定的敏感内容
confidential: 高敏感度内容，不在默认搜索/导出范围
```

### 7.2 摄取保护 (Ingest Protection)

在来源或候选晋升之前：

```text
检查 API 密钥、令牌、密码、机密
检查私有客户数据模式
检查知识的非必需个人数据
检查机密链接或截图
确认敏感度和可见性
```

### 7.3 搜索策略 (Search Policy)

默认搜索应包含：

```text
wiki/ 活跃的内部页面
personal/*/profile.md 有限字段
indexes/
```

默认搜索应排除：

```text
raw/
inbox/
confluence-mirror/
personal/*/raw
personal/*/wiki
restricted/confidential 页面，除非策略允许
演示资产
```

### 7.4 导出策略 (Export Policy)

OKF 导出默认应排除机密页面。受限页面需要明确的导出策略。

## 8. 查询安全 (Query Safety)

查询回答必须：

```text
1. 首先读取索引或搜索结果。
2. 阅读完整的顶部页面，而非仅摘要。
3. 检查 status、review_state、confidence 和 source_refs。
4. 标记过时、争议、已废弃、低置信度或非生产页面。
5. 引用页面路径和来源引用。
6. 当证据缺失时返回 unknown。
7. 当发现持久性知识缺口时建议创建候选。
```

查询回答不得：

```text
1. 将原始来源当作正式 wiki 对待，除非明确要求证据。
2. 将候选当作正式事实对待。
3. 将 Confluence 镜像当作正式事实对待。
4. 隐藏生命周期警告。
5. 未经许可使用机密页面。
```

## 9. 自动化安全 (Automation Safety)

### 9.1 允许的早期自动化

```text
生成索引
生成审查队列
生成搜索语料库
生成图谱侧车
生成 OKF 导出
从来源创建候选
创建 PR 就绪补丁
开启审查项
```

### 9.2 禁止的早期自动化

```text
自动合并正式 wiki 变更
自动删除原始来源
自动晋升个人笔记
自动导出受限页面
自动解决矛盾（无需人工负责人）
```

### 9.3 自动化审计 (Automation Audit)

每个自动化事件都应记录以下内容：

```json
{
  "event_id": "evt_<id>",
  "event_type": "candidate.created",
  "actor": "agent:<name>",
  "target": "candidate:<slug>",
  "source_refs": ["raw:<category>:<source-id>"],
  "created_at": "YYYY-MM-DDTHH:mm:ssZ",
  "result": "success | failed | needs-review"
}
```

## 10. 运营指标 (Operational Metrics)

实际使用开始后，追踪以下指标：

| 指标 | 目的 |
| --- | --- |
| 活跃页面数 | 知识库规模 |
| 无来源引用的页面 | 证据质量 |
| 超过 review_after 的页面 | 过时风险 |
| 低置信度活跃页面 | 信任风险 |
| 待审查的候选 | 工作流积压 |
| 未解决的矛盾 | 语义冲突 |
| 查询命中率 | 搜索有效性 |
| 未知答案率 | 知识缺口可见性 |
| 过时误用率 | 查询安全 |
| 负责人响应时间 | 治理健康度 |

## 11. 最终治理规则 (Final Governance Rule)

项目应致力于打造一个平淡、可检查、可审计的知识系统。

一个华丽的图谱或搜索演示，远不如一小批有来源支持、经负责人审查、感知生命周期且对 Agent 查询安全的页面有价值。
